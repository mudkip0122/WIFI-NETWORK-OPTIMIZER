# Wi-Fi 프로젝트 발표 대본

총 약 6분 30초. 발표자 이름은 첫 슬라이드에서 필요에 따라 추가하세요.

## 1. Wi-Fi 무선 네트워크 품질 분석 및 최적화 시스템

[약 30초] 안녕하세요. Wi-Fi 무선 네트워크 품질 분석 및 최적화 시스템의 개발 내용을 발표하겠습니다. 이 프로젝트는 Wi-Fi 연결 정보뿐 아니라 지연, 패킷 손실과 실제 전송 속도를 함께 측정하는 Windows 프로그램입니다. 전체 계획은 16주이며, 현재 1주차부터 8주차까지 측정과 저장, 시각화, 품질 평가 기능을 구현했습니다. 오늘은 현재 구현한 기능과 검증 결과, 향후 계획을 설명하겠습니다.

## 2. 프로젝트 배경과 목표

[약 35초] 사용자는 연결 표시만으로 실제 네트워크 상태를 파악하기 어렵습니다. 신호가 강해도 응답 지연이나 패킷 손실이 발생할 수 있고, 인터넷 경로도 결과에 영향을 줍니다. 그래서 여러 지표를 함께 측정하고 같은 조건에서 반복 확인할 수 있는 도구를 만들고자 했습니다. 최종적으로 강의실, 복도나 실습실의 위치별 품질을 비교하고 개선 방향을 제안하는 것이 목표입니다. 현재는 그 기반이 되는 수집과 평가 기능까지 구현했습니다.

## 3. 1~8주차 개발 진행

[약 35초] 1주차에는 요구사항과 기존 코드를 검토하고 개발 환경을 구성했습니다. 2주차와 3주차에 Wi-Fi 기본 정보와 네트워크 품질 측정을 추가했습니다. 4주차에는 Collector로 측정을 통합하고 시작과 중지, 자동 반복을 구현했습니다. 5주차에 SQLite 저장과 기록 조회를 연결했으며, 6주차부터 화면과 실시간 그래프를 확장했습니다. 마지막으로 8주차에 종합 품질 점수와 등급을 계산하고 Dashboard에 표시했습니다.

## 4. Wi-Fi와 네트워크 품질 측정

[약 40초] Wi-Fi 정보는 netsh와 Windows Native Wi-Fi API로 가져옵니다. RSSI는 드라이버 실측값과 신호 비율에서 환산한 추정값의 출처를 구분합니다. Ping은 게이트웨이와 외부 대상을 각각 측정해서 무선 구간과 인터넷 경로를 비교할 수 있도록 했습니다. 속도는 사용자가 예약할 때만 단일 HTTPS 연결로 측정하며 약 12MB의 시험 데이터를 사용합니다. 최대 회선 속도 측정과는 방식이 다르다는 점을 화면에 안내합니다.

## 5. 수집과 저장 구조

[약 40초] 프로그램 화면과 오래 걸리는 네트워크 측정 작업은 분리했습니다. 한 작업자가 순차 측정하고, 화면은 결과 큐를 읽어서 갱신합니다. 각 측정 결과를 SQLite에 자동 저장하기 때문에 프로그램을 다시 실행해도 과거 기록을 조회할 수 있습니다. 기록에는 AP와 실행 세션, 대상별 Ping, 속도 방향별 상태, 시각과 원본 JSON이 포함됩니다. 현재 버전에서는 측정 결과의 품질 평가도 원본 JSON에 함께 보존합니다.

## 6. Dashboard와 실시간 그래프

[약 40초] Dashboard는 연결 정보와 현재 주기의 측정값을 한 화면에 보여 줍니다. 마지막 완료 시각과 DB 저장 상태도 확인할 수 있습니다. 그래프는 RSSI, 신호 세기, Ping, 패킷 손실, 속도 중에서 선택하며 최근 100개 기록을 표시합니다. 실패나 미측정 구간은 선을 끊어서 보여 주고, 연결이나 수집 설정이 바뀌면 기록을 초기화합니다. 속도를 요청하지 않은 주기에 이전 속도 값을 재사용하지 않는 것도 중요한 구현 원칙입니다.

## 7. 품질 점수와 5단계 등급

[약 50초] 품질 평가는 각 지표를 0점부터 100점으로 환산한 뒤 가중 평균을 계산합니다. RSSI의 가중치는 30, Ping은 두 대상 합계 25, 손실은 35, 속도는 10입니다. 미측정된 속도는 0점으로 처리하지 않고 제외한 뒤 나머지 가중치를 다시 계산합니다. 그래서 평소에는 평가 범위가 90%, 속도까지 측정하면 100%입니다. 평가에는 RSSI와 최소 하나의 Ping 또는 손실 지표가 필요합니다. 이 기준은 프로젝트 초기 기준이므로 향후 실환경 데이터로 보정할 계획입니다.

## 8. 실제 네트워크 측정 결과

[약 35초] 실제 프로그램을 실행해 자동 측정과 RSSI 그래프, 품질 점수 및 DB 저장을 확인했습니다. 속도 포함 측정에서 다운로드는 약 31.56Mbps, 업로드는 약 16.56Mbps였고, 해당 측정의 종합 점수는 94.69점으로 매우 좋음 등급이었습니다. 다음 일반 측정에서는 속도를 제외하고 평가 범위가 다시 90%로 돌아오는 것도 확인했습니다. 이 숫자는 한 환경의 단일 측정 결과이며 장기 평균이나 모든 장소의 성능을 의미하지 않습니다.

## 9. 오류 처리와 검증

[약 40초] 측정 실패와 정상적인 0을 구분하도록 검증했습니다. 예를 들어 100% 손실은 손실 점수 0점으로 계산하지만 응답 지연은 측정 불가로 처리합니다. 속도 미요청과 방향별 실패도 구분하고, 연결이 바뀐 결과나 취소된 결과에서는 종합 평가를 중단합니다. 전체 자동 테스트 66개를 통과했고, 실제 화면 확인에서 발견한 하단 버튼 잘림 문제도 수정했습니다. 이후 사용자가 그래프 선택과 Wi-Fi 끊김 및 복구를 확인하고 이상 없음을 보고했습니다.

## 10. 향후 계획과 현재 성과

[약 45초] 지금까지는 Wi-Fi 품질을 측정하고 저장한 뒤, 시간에 따른 변화와 종합 점수를 확인할 수 있는 기반을 완성했습니다. 다음 9주차에는 위치 좌표와 측정을 연결하고 같은 위치의 반복 측정 평균을 구하겠습니다. 10주차와 11주차에는 Heatmap과 음영지역 탐지를 구현하고, 12주차에는 측정 근거를 제시하는 규칙 기반 진단과 개선 추천을 추가할 계획입니다. 마지막 단계에서는 실제 공간을 반복 측정하며 평가 기준을 보정하고 전체 시스템을 통합하겠습니다. 감사합니다.
