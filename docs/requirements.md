# 프로젝트 요구사항

기준일: 2026-09-24. 원본 범위: [plan.md](../plan.md).

## 목표와 대상

강의실·동아리방·복도·실습실에서 Windows 노트북을 들고 위치별로 측정하는 사용자를 대상으로 한다.
현재 연결된 AP 한 개와 선택한 무선 인터페이스를 기준으로 시작한다.
수동으로 평면도 좌표를 지정하고 반복 측정한 뒤 품질 차이와 개선 제안을 확인한다.

## 정확성 및 운영 요구사항

- RSSI 실측과 신호 % 기반 추정은 별도 출처 필드로 구분한다. 추정값을 실측으로 표시하지 않는다.
- 모든 측정에 UTC 시각과 대상 인터페이스를 기록하고 화면에서는 로컬 시각을 표시한다.
- 누락·오류·타임아웃은 null 및 상태 코드로 표현한다. 0 Mbps·0 ms와 혼동하지 않는다.
- Ping 100% 손실이면 RTT는 null이다. 패킷 송신 자체가 실패하면 손실률도 null이다.
- 속도 측정은 수동 실행을 기본으로 하며 주기적 Ping 결과에 미치는 영향을 표시한다.
- 연결 변경과 BSSID 변경을 기록하고 서로 다른 AP·대역 결과를 무조건 평균내지 않는다.
- UI 갱신과 오래 걸리는 측정 작업을 분리하고 종료 시 작업과 DB 연결을 정리한다.
- SSID/BSSID·평면도·실측 DB는 기본 로컬 보관하며 Git에 포함하지 않는다.
- 관리자 권한 없이 시작하고 접근 거부 시 필요한 설정을 안내한다.
- 실제 측정과 예제·시뮬레이션 데이터를 구별한다.

## 범위 결정

필수: Windows, 현재 연결된 AP, SQLite, 로컬 Dashboard, 수동 위치, 규칙 기반 추천.
UI는 6주차에 기존 UI 재사용 가능성을 확인하여 최종 선택하며, 수집·분석 계층과 분리한다.
추가 기능: 주변 AP 상세 스캔, 채널 혼잡도 정량화, 로밍, 머신러닝, Raspberry Pi, PDF.
채널 번호만으로 혼잡을 확정하지 않는다. AP 자동 이동·라우터 설정 자동 변경은 범위 밖이다.

## 검증 계획

2주차에는 한국어/영어 출력·미연결·권한 거부·다중 인터페이스 사례를 검증한다.
3~5주차에는 타임아웃·부분 실패·DB 재조회·종료 처리를 검증한다.
8~12주차에는 임계값 경계·누락값·보간 범위·규칙 근거를 검증한다.
14주차에는 같은 장치·방향·측정 시간·대상 서버 조건을 고정해 AP 근처/원거리/벽 뒤를 각 3회 이상 비교한다.
실측 분포에 따라 평가 기준을 보정하고 변경 이력을 남긴다.
