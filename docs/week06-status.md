# 6주차 — 실시간 Wi-Fi Dashboard

2026-10-05: 6주차 구현 및 자동 검증 완료.

## 구현

- 한 화면에 SSID·BSSID·인터페이스·RSSI·신호 %·채널·주파수 대역 표시.
- 게이트웨이와 외부 대상의 평균 Ping 및 패킷 손실을 각각 표시.
- Download·Upload 처리량을 Mbps로 표시하고 방향별 실패를 구분.
- 기존 Collector의 결과 큐를 통해 측정 완료마다 Dashboard 갱신.
- 마지막 측정 완료 시각은 저장된 finished_at을 PC 현지 시각으로 변환해 표시.
- RSSI 드라이버 실측/추정 출처, 일부 실패·실패·취소 상태를 표시.
- 누락값은 측정 불가, 속도 미요청은 이번 주기 미측정으로 표시. 이전 측정값을 재사용하지 않음.
- 자동 수집 시작/중지, 수동 속도 예약, DB 자동 저장, 기록 조회, 기존 신호 그래프 유지.

## 실행

```powershell
.\.venv\Scripts\python.exe gui.py
```

기존 `Wi-Fi Signal Strength Visualizer.py`도 동일한 Dashboard를 실행한다.
실행하면 자동 측정을 시작한다. 각 주기는 Wi-Fi·Ping 측정이 완료된 후 기본 5초를 기다린다.
외부 Ping 대상·인터페이스·대기 간격은 중지 후 변경한다.
속도는 **속도 포함 1회 예약 (약 12 MB)** 버튼을 눌러 측정한다.
자동 수집 중지 후 화면 값은 마지막 측정 기록이며 상태 문구로 이를 안내한다.
처리량은 단일 HTTPS 전송 기준이며 최대 회선 속도와 다르다.

## 검증

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

전체 55개 테스트 통과. 추가 4개 테스트는 다음을 확인한다.

- 누락된 Wi-Fi·Ping과 속도 미요청 상태.
- 0 Mbps·0 ms 및 100% 손실, 방향별 부분 속도 실패와 RSSI 출처.
- Tk Dashboard에서 연결 실패 시 이전 SSID·속도 제거.
- 실제 WifiMonitorApp에서 결과 전달·저장 상태 표시, 초기 요구 높이가 기본 창 높이 이내인지 확인.

Tk 테스트는 숨긴 창과 예제 결과로 실행했다. 실제 네트워크 수집 및 눈으로 확인하는
화면 검증은 이번 검증에 포함되지 않았다. 이전 실측 검증은 5주차 기록을 참조한다.
